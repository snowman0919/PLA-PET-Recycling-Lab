# 실제 히터 제어 코드와 열모델 연동

이 변경은 장비를 구동하지 않는 host 소프트웨어 시험이다. 시리얼, GPIO, 보드 업로드와 통전은 수행하지 않는다. source commit과 결과의 source_sha256을 함께 확인한다.

## PR 알림과 재개 기준

재개 HEAD는 a2747cdf1c8f3ea649ba2dd1da7f350414432ea0이었다. 최근 PPR 실패 메일은 24208c7f의 CI-LIGHT 34858627442이며 원인은 `current firmware evidence mismatch`다. GGM 변형 소스/manifest 누락은 649d0194에 이미 수정됐고, a2747cdf의 PR 검사 34864730099도 SUCCESS였다. 이번 수정으로 과거 메일 자체가 없어지지는 않는다. 알림 설정과 메일은 변경하지 않는다.

미커밋 초안의 중복 Makefile 시험 등록을 하나로 정리했다. 새 소스만 먼저 push하지 않고, 세 종류의 펌웨어 소스와 manifest/HEX를 함께 갱신한 커밋을 격리 검사한 뒤 전송한다. 기존 pre-push hook은 우회하지 않는다.

## 제어 코드 변경과 검증

기존 제어기는 적분값을 500으로 제한하여 Ki=0.08에서 목표온도와 오차가 0일 때 최대 40% 유지출력만 만들 수 있었다. C=100 J/K, 손실계수=0.30 W/K, 100 W 히터의 간이 플랜트에서 245 C 유지를 요구하는 새 C++ 시험은 기존 커밋 소스에서 실패했다. 실제 센서나 장비로 얻은 결과는 아니다.

적분 상한을 100/Ki로 정의하고, 출력 포화를 더 심하게 하는 방향으로 적분하지 않도록 했다. 할당된 출력에 대한 back-calculation은 유지한다. Kp=4.0 %/C, Ki=0.02 %/(C s), tracking rate=0.028 /s인 초안을 비교 시험했다. 이는 실물 PID 교정을 대체하는 계수가 아니다.

목표까지 남은 오차가 기존 최소상승량 4 C보다 클 때만 120초 상승 감시를 시작한다. 이미 목표 부근인 채 온도를 유지하는 경우를 상승 부족으로 잘못 판정하지 않는다. 실제로 낮은 온도에서 상승하지 않는 시험은 여전히 오류를 래치한다. 285 C 과온 기준, NaN/Inf 거부, 전역 오류 차단, 독립 열차단 요구는 변경하지 않는다.

같은 적분/감시 수정에서 기존 계수 2.0/0.08을 유지한 비교본과 새 계수를 두 접촉계수 및 13초 센서 지연 조건에서 비교했다. 이 비교는 모든 플랜트에서의 안정성 증명이 아니다. 원래 커밋의 실패 재현과 계수 비교를 서로 구분한다.

## 연동 범위

`power_loop_bridge.cpp`는 실제 HeaterController와 HeaterPowerAllocator를 컴파일한다. 상위 제어기의 우선순위 순환과 순간 전력 제한 순서는 별도 host 코드로 재현하므로 전체 MachineSupervisor나 AVR 실행의 대체물이 아니다. 실제 컴파일러의 사용자 헤더 의존성과 선언된 입력 집합도 대조한다. CAD 목표온도는 컴파일된 PET_PROFILE에서 직접 읽은 값과 일치해야 한다.

제어 갱신 50 ms, 온도 표본 250 ms, 2초 시간비례 출력과 PREHEATING/EXTRUSION 전력 한도를 구분한다. 계산 시간 간격을 줄여도 제어/표본 주기를 같이 줄이지 않는다. 모델은 배럴 1차원 열전달, 히터/다이 집중 열용량, 대류/복사 및 지지 열손실을 포함한다.

기존/폭만/지지만/동시 변경의 32조건, 지연/압출 4조건, 시간/공간 세분화, 열차단 개방/NaN/permission 상실을 실행한다. 수치 수렴 및 에너지 보존의 PASS와 목표온도 유지 및 외피온도 적합 여부를 분리한다.

`steady_state.py`는 목표온도를 강제했을 때 필요한 존별 전력을 역산한다. 정격보다 큰 전력이 필요한 조건은 제어기 조정만으로 해결되지 않으며 `heating_only_feasible=false`로 남긴다.

## 결과의 사용 제한

결과 파일은 `analysis/thermal_revision_v08/results/controller_replay.json`이다. 32개 비교 조건 중 목표 유지 조건은 8개이며, 수치 검사 결과와 별도로 기록한다. 수정안에서 가장 불리한 가정의 정상상태 필요전력은 Z1 약152.25 W, Z3 약109.75 W, die 약66.09 W로 현재 정격100/100/60 W를 넘는다. 따라서 이 조건의 정격 부족은 PI 계수만 바꿔 해소했다고 주장하지 않는다. 수치 검사 통과를 전체 가열계 적합으로 승격하지 않는다. 일부 조건은 목표 유지 실패 또는 HEATER_NOT_HEATING 차단이며, 낮은 접촉계수 조건에서는 히터 외피 집중온도가 300 C 비교값을 넘는다. 300 C는 공급자가 승인한 정격이 아니다.

열손실/전력 예산의 설계 보완, 후방 지지의 실제 접촉하중 검증, 뚜껑/래치/인터록/센서 장착 상세는 계속 디지털 작업이다. 이를 사용자 물리 blocker로 바꾸지 않는다. 원래 25개 gate 통과만으로 PHYSICAL_ONLY_REMAINDER를 선언하지 않는다.

후방 C형 판의 무하중 기하를 별도로 조사했을 때 개구 폭은 약 12.2091 mm, 직경34 mm 축의 위쪽 첫 접촉 변위는 약0.13388 mm였다. 해석식은0.13386 mm다. 위쪽이 열렸다는 이유만으로 축이 위로 완전히 빠진다고 단정하지 않는다. 이 확인만으로 접촉응력/열간 축정렬/실제 유지력을 검증한 것은 아니다. 불필요한 덮개를 추가하기 전에 현존 C형 접촉을 먼저 모델링한다.
